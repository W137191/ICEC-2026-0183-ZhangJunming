## 一、v1.9.2 装上新包仍崩：第二处崩溃定位

### 1. 用户反馈
- 用户覆盖安装 1.9.2（defc193）后，平板（华为 MRX-W09，HarmonyOS 4.2.0 ≈ Android 12）
  在**声振采集完成时**崩溃，发来 3 张截图。
- 截图1 系统"发热掉电监测 屡次停止运行"对话框；截图2/3 App 内置崩溃自检器
  "上次崩溃记录"窗口，显示：
  - 时间 2026-11-07 19:10:50、系统 Android 12（API 31）、设备 HUAWEI MRX-W09、线程 Thread-4
  - 异常 `ViewRootImpl$CalledFromWrongThreadException: Only the original thread that
    created a view hierarchy can touch its views`
  - 堆栈顶 `SensingActivity.startCapture$lambda$20(SensingActivity.kt:284)`

### 2. 根因
- `startCapture` 在 UI 线程 `addFlags(FLAG_KEEP_SCREEN_ON)`，但采集逻辑整体跑在后台
  `Thread { }` 里；采集结束（成功路径原 line 284 / 中断路径原 line 258）在**后台线程**直接
  `window.clearFlags(...)`。`Window.clearFlags` 触发 `onWindowAttributesChanged` 触碰 View 体系，
  Android 规定只有创建 View 的"原始线程"（主线程）能碰 View，后台线程触碰即抛此异常。
- `NoiseActivity` 测量结束（原 line 216）存在**同构隐患**。
- 手机（Android 14/15）对该检查较宽松未崩，平板（Android 12）严格检查而崩——
  属 API 级别差异，与 9.15 同源；自检器正确捕获并展示堆栈，定位零成本。

## 二、修复与构建（1.9.3）

### 1. 代码修复
- `SensingActivity.kt` 成功路径（原 line 284）与中断路径（原 line 258）的
  `window.clearFlags(FLAG_KEEP_SCREEN_ON)` 各自包进 `runOnUiThread { }`，回到主线程执行。
- `NoiseActivity.kt` 测量结束（原 line 216）同样包进 `runOnUiThread { }`。
- `addFlags` 本就在 `Thread` 块之前的主线程，无需改动；采集管线逻辑不动。
- `versionCode 12→13` / `versionName 1.9.2→1.9.3`。
