- 用户曾建议「用网络来每五分钟记录」；经评估未采纳作主方案，理由：测量值在本地（电量%/温度），

  已能在 Doze 下准时唤起，无需后端。根因非时钟漂移而是调度机制被 Doze 推迟，网络对时解不了唤起时机
- 根因定位（v1.4 残余）：主调度 `Handler.postDelayed` + 仅「晚60秒 setAndAllowWhileIdle 看门狗」；
  Doze 把非精确闹钟推迟到维护窗口 → 数十分钟空档（即遗留 39/11/13/29 跳跃）
- 修复（提交后由 CI 构建，Release `apk-latest`）：主调度改为 `AlarmManager.setExactAndAllowWhileIdle`
  （每网格点在该时刻精确挂钟，系统持有、进程死/灭屏不丢，到点唤起 TickReceiver 拉起服务补采）；
  新增 `SCHEDULE_EXACT_ALARM` 权限（targetSdk 34 / API 31+ 必需，否则 SecurityException）；
  API 21/22 退化为 `setExact`；v1.4 重启续接补满缺格逻辑保留作安全网；去除旧 60 秒粗粒度看门狗
