## CI 编译失败排障（18:10 收尾）
- 首次提交 `50cb65b`（声振采集模块）CI 失败，此后连续 4 轮迭代定位修复，最终 `a9c3637` 构建 success，APK 已发布到 `apk-latest` Release
- 排查手段：GitHub API jobs 定位失败步骤；本地无 SDK 不能复现，日志下载需 admin 权限，故把 CI 失败步骤改为「把 build.log 错误诊断发布到公开 Release ci-build-log」供直接读取
- 累积修复 4 个 Kotlin 编译错误（`SensingActivity.kt`）：
  1. `readBattery()` 第三参数误用 `Intent(ACTION_BATTERY_CHANGED)` → 应为 `IntentFilter(...)`
  2. `outDir()` 把 `getExternalFilesDir()` 的可空返回 `File?` 直接按 `File` 返回 → 用 `?: filesDir` 兜底
  3. `Unresolved reference: R`（72–80 行）：sensing 子包不会自动看见命名空间的 `com.example.batteryheatmonitor.R` → 显式 import
  4. `bufferedWriter(append=...)` 无此参数 / `appendWriter()` 该 stdlib 版本不存在 → 改用 `java.io.BufferedWriter(java.io.FileWriter(idx, exists))`
- CI 加固（`build-apk.yml`）：失败时公开错误日志 Release；成功时自动清理该调试 Release，仓库只保留 apk-latest
- 教训记录：Android 工程里每个 Kotlin 文件在子包中都要显式 import R；读错日志被 ANSI 颜色码/栈跟踪干扰，真正诊断在 compileDebugKotlin 失败前几行
