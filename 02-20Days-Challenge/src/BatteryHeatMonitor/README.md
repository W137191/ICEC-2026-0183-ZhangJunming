# 发热掉电监测 · 安卓 App（APK）

> 课程自研采数工具，一个 App 覆盖三个场景：**课题02 发热掉电监测**、**项目三 声振采集**、
> **课题06 噪声测量**。全部数据只存本机、可导出，不联网上传。

## 功能总览

### 课题02 · 发热掉电监测（主界面）

- 实时显示：电量 %、机身温度 ℃、充放电状态
- 4 个工况（与课题02一致）：`待机` / `短视频` / `导航拍摄` / `高帧率游戏`
- 后台**前台服务**采样：熄屏或切到其它 App（刷视频、打游戏）时仍持续记录
- 默认 **每 5 分钟**采样一条（间隔在 `MonitorService.EXTRA_INTERVAL_MS` 可调）
- **采样定时三级保障（v1.2 新增）**：绝对网格调度 + 看门狗闹钟 + 重启不盲采，
  进程被系统回收也能把 5 分钟网格补齐（详见下文「采样定时保障」）
- 本地 JSON 持久化（原子写入 + 损坏抢救，防丢数据），App 内实时折线图
- **导出 CSV**：`序号,工况,时间min,电量%,机身温度℃,备注`，与 `raw_data` 模板列头一致
- **温度预留接口**：默认读系统电池温度；读不到或想用第三方读数时，可在界面填入「温度兜底(℃)」手动覆盖
- 开测前检测到充电会弹提醒（充电态测"掉电"会失真）

### 项目三 · 声振采集（v3）

- 5 工况（电风扇正常/失衡/高速、吹风机冷风/热风）× 15 组 = 75 组目标
- 每采 1 组：麦克风 16kHz/16bit 单声道 WAV + 加速度计 ~100Hz CSV（前 3 列 `ax,ay,az`，
  与 `src/fft_features.py` 读取格式对齐）
- **实时音量电平条**：确认麦克风真的在收音、手机贴紧设备
- **本组备注 + 异常勾选**：写入索引备注列，采样时的环境异常是抗噪报告素材
- **组号防覆盖**：目标组号已存在时自动顺延，不静默覆盖旧数据
- **中断丢弃**：离开页面中止的采集直接丢弃，半成品不混入数据集
- **一键 ZIP 导出**：整个 Sensing 目录打包成一个文件，75 组数据一次发到电脑
- 进度可见：当前工况 N/15 组 · 总计 M/75 组

### 课题06 · 噪声测量（v1.1 新增）

- 替代市面分贝仪（只能截图、无法导出数据）：直接产出 dB 时间序列 CSV，可复算、可归档
- 5 点位（图书馆/食堂/主干道/运动场/实训室走廊）× 早午晚 = 15 格目标，时长默认 120 秒可调
- 每 100ms 计算一次 RMS → dB，实时显示当前值 + 均值/峰值/最小
- 结束后把 均值/峰值/最小 追加到 `噪声记录索引_本机.csv`，**列结构与课题06 CSV 模板完全一致，
  可直接归档合并**；备注含起止时间、时长、文件名与校准说明
- 中途中止的测量**保留**并在备注如实标注"中止@Ns"（部分数据如实记录 > 凑一个假的完整值）
- dB = `20*log10(rms/32767) + 90`：手机麦克风未校准的相对声压级，**同一设备横向对比有效**
  （市面消费级分贝仪同样未校准；本方案优势是全量原始数据可追溯）

## 采样定时保障（v1.2，修复 10-25 实测定时断档）

v1.1 实测暴露的问题：用 `postDelayed` 递归排下一次采样，进程一旦被系统回收，Handler 链
随之死亡，`START_STICKY` 重启时机不定，实测出现 **7~45 分钟采样空档**与"重启即采一条
0min 起点"的残片——表格时间列因此不规整。v1.2 用三级保障修复：

1. **绝对网格调度**：下一次采样时刻 = 会话起点 + N×间隔（墙上时钟）。单次回调早一点晚
   一点都不影响后续网格点，杜绝"越睡越晚"的漂移累积。
2. **看门狗闹钟**：每个网格点在 `AlarmManager` 挂一个 `RTC_WAKEUP` 闹钟
   （`setAndAllowWhileIdle`，无需精确闹钟权限，息屏/Doze 下仍能唤起）。进程被杀后由
   系统唤起 `TickReceiver` 重新拉起服务补采，空档不超过看门狗余量（60s）。
3. **重启不盲采**：服务被重建时**不**再补采 0min 起点，仅当网格点真正到期才补采一条；
   `时间min` 按墙上时钟如实计算，迟于网格点超过 90s 会在备注标注「定时延迟Xs(系统
   回收进程或定时被推迟)」。

另有 30 秒去重窗口：Handler 与看门狗双路触发时只记一条，防止同值重复记录。

用户可感知的效果：装 v1.2 重测，四个工况各得规整的 0/5/10/15/20/25/30 共 6 点，
CSV 时间列对齐课题02模板网格。

## 编译生成 APK

> 本地无 Android SDK 时不用编译：推送到 GitHub 后由 Actions 自动构建，
> APK 发布在 Release `apk-latest`（debug 签名统一，可直接覆盖安装）。

本地编译（可选）：

1. 打开 Android Studio → `File → Open` → 选中本目录 `BatteryHeatMonitor`（含
   `settings.gradle` 的那层）
2. 首次打开会自动下载 Gradle 与依赖（需联网），请等待 `Sync` 完成
3. `Build → Build Bundle(s) / APK(s) → Build APK(s)`
4. 编译完成后，APK 在：
`app/build/outputs/apk/debug/app-debug.apk`
5. 把 `app-debug.apk` 拷到手机安装即可（安卓允许「未知来源」安装）

> 若 Android Studio 提示 Gradle / AGP 版本不兼容，点右上角提示让它「自动升级」即可， 本项目未使用任何冷门依赖，
> 正常可一次编译通过。

## 真机使用流程

### 课题02

1. 手机装好 App，首次打开按系统提示**允许通知权限**（用于后台保活通知）
2. 选工况（如「短视频」），点 **开始监测**
3. 正常使用该工况 30 分钟；App 每 5 分钟自动采一条（共约 6 条）
4. 每个工况结束后点 **停止监测**，再切到下一个工况重新开始
5. 全部工况采完后点 **导出CSV** → 用微信/邮件/U盘把 `battery_heat_samples.csv` 取出
6. 把 CSV 内容**复制进** `01-Field-Discovery/raw_data/课题02-手机发热/发热掉电原始记录.csv`
（或直接替换其数据为实测值），配合 `报告/课题02-手机发热掉电.md` 完成分析

### 项目三（声振）

1. 主界面点 **🎙 声振采集** → 选工况（组号自动递增，已存在的组号自动顺延）
2. 手机贴紧设备外壳，点 **开始采集**；倒计时 10 秒内保持手机静置、屏幕常亮
3. 有环境异常就当场填**备注**或勾**异常**（写进索引，是抗噪报告与面试素材）
4. 每采几组点 **导出全部ZIP** 打包发到电脑——**卸载 App 会清空全部数据，务必定期导出**
5. 电脑端解压后，把 WAV/CSV 归档进 `项目三-手机声振诊断/raw_data/工况N-*/`，
   并按 `采集记录索引_本机.csv` 逐行填实仓库的 `采集记录索引.csv`

### 课题06（噪声）

1. 主界面点 **📊 噪声测量** → 选点位 + 时段（早/午晚），时长默认 120 秒
2. 手机静置（勿挡底部麦克风），点 **开始测量**，屏幕常亮等待完成
3. 完成后点 **分享 CSV+索引** 发到电脑；索引列结构与课题06模板一致，直接合并进
   `01-Field-Discovery/raw_data/课题06-噪声地图/噪声原始记录.csv` 即可
4. 同机对比有效；若中途换手机测，需在备注里说明（不同麦克风校准不同）

## 温度接口说明（预留接口）

机身温度**原生安卓可直接读** `BatteryManager.EXTRA_TEMPERATURE`（单位 0.1℃，已 ÷10）。 代码已抽象为可插拔接口
`monitor/TemperatureProvider`：

- `SystemBatteryTempProvider`：默认，读系统电池温度
- `ManualTempProvider(valueC)`：手动兜底（界面临时填值 / 后续接第三方测温 App 读数）

若某些机型读不到温度，或你想接 Root / 红外 / 第三方 App 的真实读数， 只需新增一个实现 `TemperatureProvider` 的类，并在
`MonitorService.onStartCommand` 里替换 `provider` 即可， **采样与导出逻辑无需改动**。

## 注意事项

- 采样间隔默认 5 分钟，与课题02「每5分钟记录一次」一致；想改快/慢改 `MainActivity` 里 `EXTRA_INTERVAL_MS` 的
  `5*60*1000L` 即可
- 电池温度是**电池芯**温度，并非屏幕/CPU 表面温度；不同机型读数有差异，属正常
- 保活依赖前台服务 + 唤醒锁 + 看门狗闹钟；个别国产 ROM 会强杀后台，若发现漏采，请把本
  App 加入系统「自启动/电池优化白名单」
- 采集数据都在 `Android/data/com.example.batteryheatmonitor/files/Download/` 下
  （Sensing/ 与 Noise/ 子目录），**卸载 App 会一并清空**，采集几组后就导出一次
- 本 App 仅在本地记录与导出，**不上传任何数据**
